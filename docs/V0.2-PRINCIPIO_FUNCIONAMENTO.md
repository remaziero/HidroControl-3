## `platformio.ini`

Arquivo de configuração do PlatformIO.

Define:

* ambiente de compilação `AC220`
* placa usada como base: `nodemcu-32s`
* framework: `espidf`
* velocidade do monitor serial
* tamanho de flash da AC220
* parâmetros de build

É o arquivo que permite executar:

```bash
pio run -e AC220
pio run -e AC220 -t upload
pio device monitor -e AC220
```

---

## `include/hardware.h`

Arquivo central de configuração de hardware.

Define os GPIOs usados pelo projeto:

* GPIO dos relés
* GPIO dos sensores de fluxo
* GPIO do LED blink, agora atualizado para **GPIO23**
* níveis lógicos dos relés
* tempo de retardo de desligamento
* janela de inicialização segura
* fator de conversão do sensor de fluxo

É o arquivo mais importante para adaptar o projeto a outra placa sem mexer na lógica.

Exemplo conceitual:

```cpp
#define PIN_LED_STATUS GPIO_NUM_23
#define RELAY_OFF_LEVEL 0
#define RELAY_ON_LEVEL  1
#define FLOW_K_FACTOR   6.6f
```

## `include/reles.h`

Arquivo de interface do módulo de relés.

Ele declara as funções públicas usadas pelo restante do sistema.

Funções principais:

```cpp
void reles_init();
```

Inicializa os GPIOs dos relés e força ambos para o estado desligado.

```cpp
void reles_set_frio(bool ligar);
```

Liga ou desliga o relé da bomba fria.

```cpp
void reles_set_quente(bool ligar);
```

Liga ou desliga o relé da bomba quente.

```cpp
bool reles_frio_ligado();
bool reles_quente_ligado();
```

Retornam o estado lógico atual dos relés, usado para logs e diagnóstico.

## `src/reles.cpp`

Implementa o controle físico dos relés.

Responsabilidades:

* configurar os pinos como saída
* garantir que os relés iniciem desligados
* evitar estado aleatório ao ligar
* aplicar a lógica `OFF = 0` e `ON = 1`
* registrar no log quando um relé liga ou desliga

Função principal:

```cpp
void reles_init()
```

Inicializa os relés e aplica imediatamente:

```cpp
gpio_set_level(PIN_RELE_FRIO, RELAY_OFF_LEVEL);
gpio_set_level(PIN_RELE_QUENTE, RELAY_OFF_LEVEL);
```

Isso foi a correção da **V0.2**, para resolver a instabilidade inicial das saídas.

## `include/fluxo.h`

Arquivo de interface do módulo de sensores de fluxo.

Declara as funções usadas para:

* inicializar sensores
* atualizar cálculo de vazão
* ler pulsos
* obter vazão em L/min
* saber se existe fluxo ativo
* obter o instante em que o fluxo parou

Funções principais:

```cpp
void fluxo_init();
```

Configura os GPIOs dos sensores e instala as interrupções.

```cpp
void fluxo_update();
```

Calcula a vazão com base nos pulsos contados.

```cpp
float fluxo_frio_lmin();
float fluxo_quente_lmin();
```

Retornam a vazão calculada em litros por minuto.

```cpp
bool fluxo_frio_ativo();
bool fluxo_quente_ativo();
```

Informam se há fluxo ativo.

## `src/fluxo.cpp`

Implementa a leitura dos sensores de fluxo.

Responsabilidades:

* configurar entradas com pull-up
* instalar interrupções nos GPIOs
* contar pulsos dos sensores
* calcular frequência
* converter frequência para vazão
* detectar início e fim de fluxo

A fórmula usada é:

```text
F = 6,6 × Q
```

Logo:

```text
Q = F / 6,6
```

A janela de cálculo foi ajustada para **1 segundo**, porque em baixas vazões a leitura ficou mais estável.

Funções de interrupção:

```cpp
isr_fluxo_frio()
isr_fluxo_quente()
```

São chamadas automaticamente a cada pulso do sensor.

## `src/main.cpp`

Arquivo principal do firmware.

Contém:

* `app_main()`
* task principal do HidroControl
* task de blink do LED
* lógica inicial de acionamento
* logs de diagnóstico

Como estamos usando C++ no ESP-IDF, usamos:

```cpp
extern "C" void app_main(void)
```

para que o ESP-IDF encontre corretamente a função principal.

### Função `app_main()`

Executa a sequência inicial:

1. inicializa relés
2. inicializa sensores de fluxo
3. inicializa LED de status
4. cria a task de blink
5. cria a task principal do HidroControl

### Task `task_blink`

Faz o LED de status piscar a cada **500 ms** no **GPIO23**.

Serve como heartbeat do sistema.

### Task `task_hidrocontrol`

Executa continuamente:

* atualiza sensores de fluxo
* lê vazão fria e quente
* decide estado dos relés
* aplica retardo de desligamento
* imprime logs no terminal
