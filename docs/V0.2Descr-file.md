# Documentação dos arquivos — HidroControl-3 V0.2

## 1. `platformio.ini`

Arquivo principal de configuração do PlatformIO.

Define o ambiente de compilação chamado:

```ini
[env:AC220]
```

Esse ambiente usa:

```ini
platform = espressif32
board = nodemcu-32s
framework = espidf
```

Ou seja, o projeto está sendo compilado para ESP32 usando **ESP-IDF**, não Arduino.

Também define:

```ini
monitor_speed = 115200
monitor_rts = 0
monitor_dtr = 0
```

Essas opções configuram o monitor serial e evitam reset automático indesejado por RTS/DTR em algumas placas.

Define ainda:

```ini
board_upload.flash_size = 2MB
board_build.flash_size = 2MB
```

Isso foi necessário porque a AC220 detectada possui **flash de 2 MB**, não 4 MB.

## 2. `CMakeLists.txt` da raiz

Arquivo de configuração CMake principal do projeto ESP-IDF.

```cmake
cmake_minimum_required(VERSION 3.16.0)
include($ENV{IDF_PATH}/tools/cmake/project.cmake)
project(HidroControl-3)
```

Funções:

* define a versão mínima do CMake;
* carrega o sistema de build do ESP-IDF;
* define o nome do projeto como `HidroControl-3`.

Esse arquivo é obrigatório em projetos ESP-IDF.

---

## 3. `src/CMakeLists.txt`

Arquivo que registra os arquivos-fonte do projeto como componente ESP-IDF.

```cmake
FILE(GLOB_RECURSE app_sources ${CMAKE_SOURCE_DIR}/src/*.*)

idf_component_register(SRCS ${app_sources})
```

Ele faz uma busca recursiva por todos os arquivos dentro de `src/` e registra tudo como fonte do componente principal.

Na prática, isso permite compilar automaticamente:

```text
src/main.cpp
src/fluxo.cpp
src/reles.cpp
```

sem precisar listar cada arquivo manualmente.

## 4. `include/hardware.h`

Arquivo central de configuração de hardware.

Ele concentra os pinos e constantes físicas do projeto.

### Relés

```cpp
#define PIN_RELE_FRIO      GPIO_NUM_16
#define PIN_RELE_QUENTE    GPIO_NUM_17
```

Define os GPIOs usados para controlar os dois relés da AC220:

* relé da bomba fria;
* relé da bomba quente.

### Sensores de fluxo

```cpp
#define PIN_FLUXO_FRIO     GPIO_NUM_25
#define PIN_FLUXO_QUENTE   GPIO_NUM_26
```

Define os GPIOs usados para leitura dos sensores de fluxo.

Cada sensor gera pulsos digitais que são contados por interrupção.

### LED de status

```cpp
#define PIN_LED_STATUS GPIO_NUM_23
```

Define o GPIO usado para o LED heartbeat, que pisca a cada 500 ms.

Esse LED serve como indicação de que o firmware está vivo.

### Níveis dos relés

```cpp
#define RELAY_OFF_LEVEL 0
#define RELAY_ON_LEVEL  1
```

Define explicitamente a lógica dos relés:

```text
0 = relé desligado
1 = relé ligado
```

Essa definição foi ajustada na V0.2 para eliminar instabilidade inicial nas saídas simuladas no Wokwi.

### Tempos de controle

```cpp
#define DELAY_OFF_MS       5000
#define STARTUP_INHIBIT_MS 3000
```

`DELAY_OFF_MS` define o retardo de desligamento dos relés após o fim do fluxo.

`STARTUP_INHIBIT_MS` impede que os relés sejam acionados durante os primeiros 3 segundos após o boot.

### Fator de fluxo

```cpp
#define FLOW_K_FACTOR 6.6f
```

Define a constante de conversão do sensor de fluxo.

A fórmula usada é:

```text
F = 6,6 × Q
```

Logo:

```text
Q = F / 6,6
```

onde:

* `F` é a frequência em Hz;
* `Q` é a vazão em L/min.

## 6. `src/reles.cpp`

Implementa o controle físico dos relés.

### Variáveis internas

```cpp
static bool s_frio = false;
static bool s_quente = false;
```

Guardam o estado lógico atual dos relés.

Essas variáveis evitam escritas repetidas no mesmo GPIO quando o estado não mudou.

### `reles_init()`

```cpp
void reles_init()
```

Responsável por:

1. pré-carregar os GPIOs dos relés no nível desligado;
2. configurar os GPIOs como saída;
3. ativar pull-down interno;
4. confirmar novamente o nível desligado;
5. zerar os estados internos.

Trecho central:

```cpp
gpio_set_level(PIN_RELE_FRIO, RELAY_OFF_LEVEL);
gpio_set_level(PIN_RELE_QUENTE, RELAY_OFF_LEVEL);
```

Isso garante que as saídas iniciem em nível `0`.

Esse foi o ajuste principal da V0.2 para combater saídas aleatórias ao ligar.

### `reles_set_frio(bool ligar)`

Liga ou desliga o relé frio.

Se o estado solicitado for igual ao estado atual, a função retorna sem fazer nada:

```cpp
if (ligar == s_frio) return;
```

Se houver mudança, atualiza o GPIO:

```cpp
gpio_set_level(PIN_RELE_FRIO, ligar ? RELAY_ON_LEVEL : RELAY_OFF_LEVEL);
```

E imprime log:

```cpp
RELE FRIO: LIGADO
```

ou:

```cpp
RELE FRIO: DESLIGADO
```

### `reles_set_quente(bool ligar)`

Tem a mesma lógica da função anterior, mas aplicada ao relé quente.

### `reles_frio_ligado()`

Retorna `s_frio`.

### `reles_quente_ligado()`

Retorna `s_quente`.

## 8. `src/fluxo.cpp`

Implementa a leitura dos sensores de fluxo.

### Uso de `std::atomic`

```cpp
static std::atomic<uint32_t> s_pulsos_frio{0};
static std::atomic<uint32_t> s_pulsos_quente{0};
```

Os contadores de pulsos são atômicos porque são alterados dentro de interrupções.

Isso evita problemas de concorrência entre:

* ISR dos sensores;
* task principal que lê os contadores.

Também corrigiu o erro de compilação causado pelo uso de `volatile++` em C++ moderno.

### ISRs dos sensores

```cpp
static void IRAM_ATTR isr_fluxo_frio(void *arg)
```

Executa a cada pulso no sensor frio.

Incrementa:

```cpp
s_pulsos_frio.fetch_add(1, std::memory_order_relaxed);
```

A versão quente faz o mesmo para `s_pulsos_quente`.

### `fluxo_init()`

Configura os GPIOs dos sensores como entrada:

```cpp
io_conf.mode = GPIO_MODE_INPUT;
```

Ativa pull-up interno:

```cpp
io_conf.pull_up_en = GPIO_PULLUP_ENABLE;
```

Configura interrupção por borda de descida:

```cpp
io_conf.intr_type = GPIO_INTR_NEGEDGE;
```

Depois instala o serviço de interrupção:

```cpp
gpio_install_isr_service(0);
```

e adiciona as ISRs aos pinos dos sensores.

### `fluxo_update()`

Calcula a vazão a cada 1 segundo:

```cpp
if (dt_us < 1000000) {
    return;
}
```

Essa janela foi ajustada de 0,5 s para 1 s, pois o teste no Wokwi mostrou melhor estabilidade em baixas vazões.

A função:

1. lê os pulsos acumulados;
2. calcula a diferença desde a última medição;
3. calcula a frequência em Hz;
4. converte Hz para L/min;
5. determina se o fluxo está ativo;
6. registra o instante em que o fluxo parou.

### Cálculo de vazão

```cpp
float hz_frio = (float)d_frio / dt_s;
s_frio_lmin = hz_frio / FLOW_K_FACTOR;
```

A mesma lógica é aplicada ao fluxo quente.

### Fluxo ativo

```cpp
bool novo_frio_ativo = s_frio_lmin > 0.10f;
```

O fluxo é considerado ativo quando a vazão passa de `0,10 L/min`.

### Detecção de parada

```cpp
if (s_frio_ativo && !novo_frio_ativo) {
    s_last_stop_frio_ms = now_ms;
}
```

Isso registra o momento em que o fluxo deixa de existir.

Esse tempo será usado para manter o relé ligado durante o retardo de desligamento.

## 9. `src/main.cpp`

Arquivo principal do firmware.

Contém:

* função principal `app_main()`;
* task principal do controle hidráulico;
* task de blink do LED;
* função de tempo em ms;
* função auxiliar de retardo de desligamento.

### `millis32()`

```cpp
static uint32_t millis32()
```

Converte o tempo do ESP-IDF de microssegundos para milissegundos:

```cpp
esp_timer_get_time() / 1000
```

Substitui o `millis()` usado no Arduino.

### `hold_off_active()`

```cpp
static bool hold_off_active(uint32_t last_stop_ms, uint32_t now_ms)
```

Verifica se o retardo de desligamento ainda está ativo.

Se `last_stop_ms == 0`, retorna `false`.

Isso evita que os relés liguem indevidamente no boot.

### `task_hidrocontrol()`

Task principal do sistema.

Executa em loop contínuo.

A cada ciclo:

1. lê o tempo atual;
2. chama `fluxo_update()`;
3. lê os estados de fluxo;
4. decide o estado dos relés;
5. aplica o retardo de desligamento;
6. atualiza os relés;
7. imprime log a cada 1 segundo.

### Inibição inicial

```cpp
if (now > STARTUP_INHIBIT_MS)
```

Durante os primeiros 3 segundos após o boot, os relés não são acionados.

Isso aumenta a segurança na partida.

### Lógica atual

Na versão atual, a lógica implementada é modo **NORMAL**:

```text
fluxo frio   -> relé frio
fluxo quente -> relé quente
```

com retardo de desligamento.

Os modos DUO e MIX ainda não foram implementados nesta fase.

### Log

A cada 1 segundo, imprime:

* pulsos frio;
* vazão fria;
* fluxo frio ativo;
* estado do relé frio;
* pulsos quente;
* vazão quente;
* fluxo quente ativo;
* estado do relé quente.

### `task_blink()`

Task dedicada ao LED de status.

Configura o GPIO23 como saída:

```cpp
gpio_set_direction(PIN_LED_STATUS, GPIO_MODE_OUTPUT);
```

E alterna o estado a cada 500 ms:

```cpp
vTaskDelay(pdMS_TO_TICKS(500));
```

Esse LED funciona como heartbeat do sistema.

### `app_main()`

Função principal do ESP-IDF.

Como o projeto usa C++, foi declarada assim:

```cpp
extern "C" void app_main(void)
```

para evitar alteração do nome da função pelo compilador C++.

Sequência atual:

1. imprime banner de inicialização;
2. inicializa relés;
3. inicializa sensores de fluxo;
4. cria `task_hidrocontrol`;
5. cria `task_blink`.

# Observações de desenvolvimento

## Estado funcional atual

A versão atual já possui:

```text
- ESP-IDF + C++
- relés com inicialização segura
- sensores de fluxo por interrupção
- cálculo de vazão validado
- janela de medição de 1 segundo
- retardo de desligamento
- LED heartbeat no GPIO23
```

## Validação no Wokwi

Foram usados geradores de clock para simular sensores de fluxo:

```text
33 Hz  -> aproximadamente 5,00 L/min
6,6 Hz -> aproximadamente 1,00 L/min
```

Isso validou a fórmula:

```text
Q = F / 6,6
```

## V0.2

A V0.2 corresponde ao ajuste de estabilidade das saídas no boot:

```text
Ajustado instabilidade das saídas ao ligar
```

A lógica dos relés foi padronizada para:

```text
OFF = 0
ON  = 1
```

com pull-down interno habilitado.
